# 🐾 왈씨 Walssi — 지금, 우리 아이 산책 괜찮을까요?

날씨 API를 붙여보는 실습용 대시보드로 시작해, **반려견 산책 가능 여부를 판정해주는 서비스**로
전환한 Vue 3 프로젝트다. Options API 연습부터 Composition API, Vue Router, Pinia, 외부 API
연동, 지도, 알림, 기록 관리까지 SKALA Day 2~4 과제를 순서대로 쌓아 올린 결과물이다.

- **배포 주소**: [https://temporary-express-azure-l1slvx3.vercel.app](https://temporary-express-azure-l1slvx3.vercel.app)
- **개발 전체 기록**: [markdown/README\_전체개발기록.md](markdown/README_전체개발기록.md) — 6단계 전체 요구사항·설계 판단·버그 수정·검증 방법을 시간순으로 정리한 원본 문서(이 README는 그 기록을 최종 제출용으로 요약·재구성한 것)

## 1. 아이디어 — 왜 날씨 대시보드가 산책 판정 서비스가 됐나

Day 2~3 과제는 "도시별 날씨를 검색·비교하는 대시보드"였다. 컴포넌트 분리, 라우팅, 상태관리를
연습하기엔 좋은 소재였지만, 정작 완성된 대시보드는 **"그래서 이 정보로 뭘 하라는 거지?"**라는
질문에 답하지 못했다. 온도·습도·풍속 숫자를 나열할 뿐, 그 숫자가 어떤 행동으로 이어져야 하는지는
사용자의 몫으로 남겨져 있었다.

그래서 4단계부터 컨셉을 좁혔다: **"오늘 날씨가 어떤가"가 아니라 "지금 이 날씨에 우리 개를
데리고 나가도 되는가"**를 답해주는 서비스로 전환했다. 이유는 세 가지다.

1. **판정 대상이 명확하면 설계가 쉬워진다.** 날씨 대시보드는 "어떤 정보를 보여줄까"부터
   막막했지만, "산책 가능 여부"는 입력(기온·습도·지면온도·강수·바람·대기질·견종 특성)과
   출력(좋음/주의/제한/위험 4단계 + 가능 시간)이 뚜렷해 도메인 로직(`domain/walkRules.js`)을
   먼저 순수 함수로 짜고 그 위에 화면을 얹는 순서가 자연스러웠다.
2. **반려견은 사람과 다른 임계값을 가진다.** 반려견은 사람보다 지면에 가깝고(체고가 낮아
   복사열에 더 노출됨), 발바닥 패드가 뜨거운 아스팔트에 직접 닿고, 땀샘이 발바닥에만 있어
   체온 조절이 사람만큼 효율적이지 않다. "사람 기준 날씨 정보"와 "개 산책 기준 판정"이
   갈리는 지점(지면온도 실측, 견종·연령·체중별 위험도 보정)이 이 서비스만의 차별점이 됐다.
3. **기존에 만든 것을 버리지 않고 승격시킬 수 있었다.** 도시별 날씨 비교 기능은 쓸모가
   없어진 게 아니라 "동네 날씨 확인"이라는 보조 기능으로 강등됐고(`/weather`), 위험
   경보 카드는 "산책 주의보"(`/weather/alerts`)로 이름이 바뀌었을 뿐 로직은 그대로
   재사용됐다. 새 컨셉이 기존 코드를 갈아엎지 않고 **위에 얹히는 구조**였다는 게 이
   피벗이 과제 범위 안에서 가능했던 이유다.

이름 "왈씨(Walssi)"는 "왈왈(강아지 짖는 소리) + 날씨"를 합성한 말이다.

## 3. 기술 스택

| 분류          | 기술                                                                          | 비고                                                         |

| 프레임워크    | Vue 3 (Composition API, `<script setup>`)                                     |                                                              |
| 빌드 도구     | Vite                                                                          |                                                              |
| 라우팅        | Vue Router 5                                                                  | 지연 로딩(`() => import(...)`) + catch-all 라우트            |
| 상태관리      | Pinia                                                                         | `weatherStore` / `configStore` / `dogStore` / `walkLogStore` |
| HTTP          | Axios                                                                         |                                                              |
| UI 라이브러리 | Element Plus                                                                  | 체크박스·태그·버튼 등                                        |
| 지도          | Leaflet + OpenStreetMap                                                       | 키 발급 없이 즉시 재현 가능해서 선택                         |

| 외부 API      | OpenWeatherMap(현재 날씨/예보/대기질), 기상청 도로기상관측자료(노면 실측온도) |                                                              |
| 브라우저 API  | Geolocation, Notification, localStorage                                       |                                                              |
| 린트/포맷     | ESLint(+oxlint), Prettier                                                     |                                                              |
| 배포          | Vercel                                                                        |                                                              |

## 4. 실행 방법

```bash
npm install
cp .env.example .env.local   # 아래 표의 키를 채운다
npm run dev                  # http://localhost:3000
```

| 환경변수                 | 용도                                   | 필수 여부                        |
| ------------------------ | -------------------------------------- | -------------------------------- |
| `VITE_OWM_API_KEY`       | OpenWeatherMap 현재 날씨·예보·대기질   | 필수                             |
| `VITE_KMA_AUTH_KEY`      | 기상청 도로기상관측자료(노면 실측온도) | 없으면 기온 기반 추정값으로 폴백 |
| `VITE_ADSENSE_CLIENT_ID` | Google Ad Placement(리워드 광고)       | 없으면 테스트용 placeholder 사용 |
| `VITE_KAKAO_APP_KEY`     | 카카오맵 장소 검색 SDK                 | 없으면 장소 검색만 비활성화      |

```bash
npm run build      # 프로덕션 빌드 (dist/)
npm run preview    # 빌드 결과 로컬 미리보기
npm run lint        # oxlint + eslint
npm run format      # prettier
```

## 5. 배포

[Vercel](https://vercel.com)에 정적 빌드(`vite build`)로 배포했다. 배포 주소는 상단 "배포
주소" 항목을 참고. Vercel 대시보드에서 위 4절의 환경변수를 프로젝트 설정(Environment
Variables)에 등록해야 실데이터 연동(날씨·노면온도·지도·광고)이 정상 동작한다. 키가
비어있어도 앱 자체는 빌드·구동되며, 개별 기능만 안내 문구와 함께 조용히 폴백한다.

> **참고**: 이 세션에는 Vercel 로그인(OAuth) 절차를 대신 진행할 수 없어, `vercel deploy`를
> 로그인 없이 실행하는 **클레임 가능한 익명 배포**로 올렸다. 익명 배포는 클레임하지 않으면
> 일정 시간 후 만료된다 — 계속 유지하려면 아래 링크에서 본인 Vercel 계정으로 가져와야 한다.
> 이후 재배포·환경변수 설정도 계정을 클레임한 뒤 Vercel 대시보드 또는 `vercel` CLI로 진행하면 된다.
>
> **클레임 링크**: https://vercel.com/claim-deployment?code=78949864-f203-48a0-b876-c263a3558679
