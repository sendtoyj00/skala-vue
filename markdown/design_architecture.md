## 1. 이 문서가 지금 다루는 것

### 1.1 이미 해결된 것 `[현재]`

직전 개정에서 지적했던 하드코딩 문제는 해소됐다. 실측 기준:

| 이전 문제 | 현재 |

| 주 버튼 배경색 4종 / 위험 빨강 5종 / 반경 6종 | 역할 기반 토큰 1벌로 통합 (`base.css:5-58`) |

| 배지가 P0/P2에 동일 강도 | 배지는 무채색 텍스트로 통일, 위험 강조는 `WeatherCard` 좌측 테두리·플래그가 전담 (`WeatherBadge.vue:25-39`, `WeatherCard.vue:61-75`) |

### 1.2 이 개정이 다루는 것

컨셉이 "이 개가 산책해도 되는가"로 좁혀지면서([service_architecture.md](./service_architecture.md) 1절), **화면의 주인공이 날씨 카드에서 산책 판정으로 바뀐다.** 새 과제는 색을 고르는 일이 아니라 다음 셋이다.

1. **판정 결과의 시각 언어** — "15분 가능"을 어떤 크기·색·형태로 말할 것인가
2. **추정값의 표기** — 지면온도는 관측값이 아니다. 관측값처럼 보이면 안 된다
3. **강등된 요소의 재배치** — 날씨 카드·배지가 주인공 자리에서 내려온다

> 디자인은 **정보의 우선순위를 시각 속성으로 번역하는 일**이다. 우선순위가 바뀌면 색이 아니라 우선순위표부터 다시 쓴다.

이 문서가 규정하지 않는 것: 브랜드 아이덴티티·로고, 애니메이션 연출 문법, 어떤 데이터를 보여줄지(서비스 문서), 상태를 누가 소유할지(Vue 문서).

## 2. 정보 우선순위

### 2.1 도출 논리

```text
컨셉: 이 개가 지금 나가도 되는지 판단해 준다
  → 어떤 정보가 견주의 행동을 바꾸는가?
  → 행동을 바꾸는 힘이 큰 순서로 줄을 세운다
```

> 정보 우선순위는 "무엇이 중요해 보이는가"가 아니라 **"이 정보를 못 보면 사용자가 잘못된 행동을 하는가"**로 결정한다.

### 2.2 단계 정의

정보 축(P0~P4)과 도구 축(T1~T2), 광고(X)를 분리한다.

| 단계 | 포함 정보 | 이전 단계 | 상태 |
| --- | --- | --- | --- |
| **P0** 산책 판정 | 판정 단계, 가능 시간(분), 지면온도 경고 | 신규 | `[예정]` |
| **P1** 대안 시간대 | 시간대별 적합도, 다음 가능 시각 | 신규 | `[예정]` |
| **P2** 판정 근거 | 추정 지면온도, 기온, 습도, 대상 개체 | P1·P2에서 승계 | `[예정]` |
| **P3** 원시 날씨 | 날씨 상태, 풍속, 지역 목록 | **P0·P1에서 강등** | `[현재]` |
| **P4** 부가 정보 | 서비스 소개, 관측 시각, **면책 안내** | 승계 + 신규 | `[현재]` |
| **T1** 주 탐색 | 전역 네비게이션, 대상 개체 전환 | 승계 | `[현재]` |
| **T2** 보조 탐색 | 지역 검색, 단위 토글 | 승계 | `[현재]` |
| **X** 광고 | 외부 슬롯(판정·타임라인 화면 금지) | 승계 | `[예정]` |

**P3 강등이 이 개정의 핵심 변화다.** 이전에는 지역 목록과 날씨 상태가 P0~P1이었으나, 견주는 8개 도시를 비교하지 않고 자기 동네 하나만 본다. 날씨 수치는 판정을 만드는 재료이지 산출물이 아니다.

**면책 안내를 P4에 넣되 숨기지 않는 이유**: 서비스 문서 11절이 상시 노출을 요구한다. P4는 "작게"이지 "없음"이 아니다.

### 2.3 우선순위 → 시각 속성 번역표

| 단계 | 크기 | 색·대비 | 강조 수단 |
| --- | --- | --- | --- |
| **P0** | 화면 내 최대(가능 시간 숫자) | 산책 단계색, 대비 4.5:1↑ | **배경 채움+아이콘+테두리**(유일하게 3중 허용) |
| **P1** | 본문의 1.0~1.15배 | 단계색을 저채도로 재사용 | 형태(막대 길이)로 표현, 2중까지 |
| **P2** | 본문~본문보다 작게 | 기본 텍스트 | 라벨만 약하게. 지면온도는 예외(2.5) |
| **P3** | 본문보다 작게 | muted | 없음 |
| **P4** | 최소(단, AA 기준 준수) | 최저 대비 | 없음 |
| **X** | 슬롯 고정 | 서비스 색 사용 금지 | "광고" 라벨 필수, 단계색 금지 |

### 2.4 파생 규칙

1. **배경 채움은 P0과 광고 라벨에만.** 산책 판정 카드가 화면에서 유일하게 채워진 요소다.
2. **색만으로 단계를 표현하지 않는다.** 산책 단계는 아이콘/텍스트를 반드시 동반.
3. **강조 수단은 단계당 정해진 개수를 넘지 않는다.**
4. **상위 단계는 하위 단계보다 위에 온다**(예외: T1은 항상 최상단, P4는 항상 하단).
5. **P2 판정 근거는 감추지 않는다.** 접어두더라도 접혀 있다는 표시는 남긴다(서비스 문서 11절 근거 공개).

### 2.5 지면온도의 예외 취급

지면온도는 P2(판정 근거)에 속하지만 **시각적으로는 P1 수준을 허용한다.** 이유:

- 이 값이 서비스의 고유 정보 가치다. 사용자가 모르던 정보를 알려주는 유일한 지점이다.
- 기온과 나란히 두면 둘 중 어느 쪽이 위험 신호인지 구분되지 않는다.

단, **관측값처럼 보이면 안 된다**(서비스 문서 4.2). 규격:

| 항목 | 규격 |
| --- | --- |
| 표기 | 값 앞이나 위에 **"추정"** 라벨 필수 |
| 형태 | 실선 테두리 금지 — 점선 또는 배경 없는 형태로 관측값과 구분 |
| 색 | 단계색을 쓰되 채도를 한 단계 낮춘다 |
| 병기 | 기온과 함께 보여 격차가 드러나게 한다("기온 31℃ / 추정 지면 58℃") |

### 2.6 강조 총량 규칙

> 모든 것을 강조하면 아무것도 강조되지 않는다.

| 대상 | 상한 |
| --- | --- |
| 화면당 최강 강조(배경+최대크기+아이콘) | **1개** — 산책 판정 카드 |
| 화면당 단계색 계열 | 1개 계열 |
| 카드당 배지 | 최대 2개, 그중 P0은 1개 |
| 목록에서 위험 비율이 50%를 넘을 때 | 색을 늘리지 말고 **정렬**로 해결 |

마지막 항목은 이미 적용돼 있다 — 위험 지역을 상단으로 정렬한다(`WeatherHomeView.vue:84`). 목업 8건 중 4건이 위험이라 색만으로는 변별되지 않기 때문이다.

## 3. 화면 배치 기준

### 3.1 원칙

1. **첫 화면에는 P0만.** 홈에 들어오면 산책 판정이 먼저 보인다. 지역 목록은 아래로 내려간다.
2. **판정은 항상 같은 자리**(화면 최상단). 스크롤 없이 보여야 한다.
3. **"안 된다"로 끝내지 않는다.** 판정이 `unsafe`/`limited`면 대안 시간대(P1)가 **같은 화면에** 이어진다. 서비스 문서 5절 흐름 C가 끊기면 서비스가 거절만 하는 서비스가 된다.
4. **탐색 도구는 결과 바로 위, 결과보다 작게.**
5. **한 화면에 하나의 주 콘텐츠 영역만.**
6. **폭은 콘텐츠가 정한다**(`max-width` + `width:100%`). `[현재]` `layout.css:42-46`

### 3.2 앱 셸 `[현재→수정]`

현재 `App.vue`는 네비게이션 + `RouterView` 1개의 단일 셸이다. 추가할 것은 대상 개체 표시와 푸터다.

면책 안내는 셸 레벨에는 아직 없지만, `[현재]` `WeatherHomeView.vue:110-115`에 판정 카드 하단 한 줄로 최소 배치돼 있다(F-30, service_architecture.md 3.5 — F-23과 동시 투입 원칙). 셸로 승격은 여전히 `[예정]`.

```text
┌ 헤더: 서비스명 [판정│타임라인│지역│소개] [대상 개체] [단위] ┐  T1/T2
│ 주 콘텐츠 — <RouterView/> 1개                              │  P0~P3
│ 면책 안내                                                   │  P4
│ 푸터: 데이터 출처·추정 방식 안내                             │  P4
└────────────────────────────────────────────────────────────┘
```

**대상 개체 표시를 헤더에 두는 이유**: 다견 가정에서 어느 아이 기준 판정인지 모르면 판정 전체를 신뢰할 수 없다(서비스 문서 4.7). 화면마다 반복하지 않고 셸에 한 번만 둔다.

`<RouterView/>`는 앱 셸에 1개만 둔다 `[현재]`.

- **WalkHomeView** `[예정]` — 새 홈: 판정 카드(P0) → 대안 시간대(P1) → 판정 근거 접기(P2) → 면책(P4). 프로필이 없으면 판정 자리에 온보딩이 들어간다.

## 4. 컴포넌트 시각 규격

| 원칙 | 이유 |

### 4.2 WalkVerdictCard `[예정]` — 서비스의 얼굴

화면에서 **유일하게 배경이 채워진 요소**다. 목표 위계:

```text
┏━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┓
┃ 🐕 아이콘 + 단계 라벨(P0)             ┃  ← 색+아이콘+텍스트 3중
┃                                       ┃
┃   15분                                ┃  ← 화면 내 최대 크기
┃   그늘 위주로, 물 챙기세요             ┃  ← 지시문, 단정 아닌 조건부
┃                                       ┃
┃ 추정 지면 58℃ · 기온 31℃ · 습도 70%  ┃  ← P2, 근거 요약
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛
```

| 항목 | 규격 |
| --- | --- |
| 배경 | 단계색 채움 (`--color-walk-*`) |
| 가능 시간 | `--font-size-2xl` 이상, 화면 내 최대 |
| 지시문 | 최대 2개(서비스 문서 4.5). 단정 금지 |
| `unsafe` 상태 | **가능 시간 자리에 "지금은 어려워요"** + 다음 가능 시각. 빈칸이나 "0분"으로 두지 않는다 |
| 대상 개체 | 어느 아이 기준인지 카드 안에 표기 |

**"0분"을 쓰지 않는 이유**: 숫자 0은 측정 결과처럼 보이고, 다음 행동을 제시하지 못한다.

### 4.3 PawTempIndicator `[예정]`

지면온도 전용. 2.5절 규격을 따른다.

- **색 단독 의존 금지** — 색 + 아이콘(🐾) + 수치 텍스트 3중.
- 기온과 **격차**를 보이는 것이 목적이므로 둘을 나란히 배치한다.
- "추정" 라벨은 축약하지 않는다(툴팁 뒤로 숨기지 않는다).

### 4.4 WalkWindowTimeline `[예정]`

- 24시간 가로 막대, 시간대별 단계색.
- **현재 시각 마커 고정.** 지금이 어디인지 없으면 "저녁 7시"가 얼마나 남았는지 읽을 수 없다.
- 색 단독 의존 금지 — 가능 구간에 텍스트 라벨을 얹는다.
- 모바일에서 가로 스크롤 대신 **접기**를 쓴다(가로 스크롤은 마커 위치를 잃는다).

### 4.5 DogSelector / DogAvatar `[예정]`

- `DogSelector`: 앱 전체에 하나뿐이므로 셸 헤더에 둔다. 개체가 1마리면 **표시만 하고 조작 요소를 만들지 않는다**.
- `DogAvatar`: 사진이 없을 때가 기본이다. 이니셜·기본 아이콘으로 자리를 유지한다.

### 4.6 WeatherBadge `[현재]`

배경 채움과 판단 문구를 모두 회수했다(`WeatherBadge.vue`). 위험/안전 모두 같은 무채색 텍스트로 렌더링되며, `emphasis` prop을 받지 않는다 — 화면별 강조 차등은 `WeatherCard`의 좌측 테두리·플래그가 전담한다(4.7).

| 항목 | 이전 | 이후 |
| --- | --- | --- |
| 역할 | 행동 권고("외출을 삼가세요") | **날씨 상태 표시만** (`weatherRules.js`의 `RECOMMENDATIONS` 문구를 상태 서술형으로 교체) |
| 배경 채움 | 위험 시 사용 | **전면 금지** — 채움은 `WalkVerdictCard`가 독점(`WeatherBadge.vue:25-39`, 예외 없음) |
| 위치 | 카드 본문 | 카드 상단 보조 표기 |

**배경 채움을 회수하는 이유**: 한 화면에 채워진 요소가 둘이면 어느 쪽이 결론인지 알 수 없다. 판단은 `WalkVerdictCard` 하나만 한다(서비스 문서 1.4). 이 규칙은 화면(경보·상세 포함) 예외 없이 적용된다 — `emphasis`는 이제 `WeatherCard`/`WeatherList`에만 남아 테두리·플래그 강도를 조절할 뿐, `WeatherBadge`의 배경에는 관여하지 않는다.

### 4.7 승계 컴포넌트 요지

- **WeatherCard** `[현재]`: 좌측 4px 바의 의미를 "날씨 위험"에서 **"해당 지역 산책 불가"**로 재정의. 형태는 유지(`WeatherCard.vue:61-75`).
- **SearchBar** `[현재→수정]`: 라벨을 `h3`로 마크업하지 않는다 — 도구가 정보 섹션과 같은 위계를 갖는다. `<label for>`로 교체 `[예정]`.
- **StatusBar** `[현재]`: 조작 피드백 전용. 좌측 정렬·비성공색 적용 완료. 로딩·오류는 담지 않는다.
- **UnitToggler** `[현재→수정]`: 세그먼트 형태로 바꾼다 `[예정]` — 버튼 하나로는 다음 상태를 예측할 수 없다.
- **ErrorState / WeatherCardSkeleton** `[현재]`: 6절 규격을 이미 충족한다.

## 5. 디자인 토큰

### 5.1 네이밍 규칙

> 이름은 **색 이름이 아니라 역할 이름**으로 짓는다. `--color-red`가 아니라 `--color-danger`.

임계값 정정으로 색 배정이 바뀌어도 컴포넌트를 고치지 않아도 된다.

### 5.2 현재 토큰 `[현재]`

`base.css:5-58`에 정의돼 있다.

| 분류 | 토큰 |
| --- | --- |
| 표면 | `--color-surface`, `--color-surface-sunken` |
| 경계·텍스트 | `--color-border`, `--color-text`, `--color-text-muted` |
| 의미 | `--color-danger` / `warning` / `safe` / `info` + 각 `-surface` 쌍 |
| 강조 | `--color-primary`, `--color-primary-surface`, `--color-on-primary`, `--color-on-danger` |
| 타이포 | `--font-sans`, `--font-size-xs~2xl`(12/14/16/18/20/24/32) |
| 간격 | `--space-1~8` (4배수 스케일) |
| 반경 | `--radius-sm/md/lg/full` (4/8/12/999) |
| 그림자 | `--shadow-sm/md` (2종) |

### 5.3 신규 — 산책 단계 색 `[예정]`

> 4단계가 **단조 증가**하는 채도·대비를 갖는다. 순서가 뒤집히면 판정이 뒤집혀 보인다.

| 토큰 | 단계 | 의미 |
| --- | --- | --- |
| `--color-walk-good` | good | 제한 없음 |
| `--color-walk-caution` | caution | 시간 제한 있음 |
| `--color-walk-limited` | limited | 짧게만, 조건부 |
| `--color-walk-unsafe` | unsafe | 지금은 어려움 |

각 토큰은 `-surface`(연한 배경)와 `-on`(그 위 텍스트) 쌍을 함께 갖는다 — 라이트/다크 양쪽에서 4.5:1을 보장하려면 텍스트 색을 배경과 함께 정의해야 한다.

**의미 토큰(`danger`/`warning`/`safe`)을 재사용하지 않는 이유**: 날씨 위험(F-05)과 산책 단계(F-23)는 다른 축이다. 같은 토큰을 쓰면 "날씨는 위험한데 산책은 가능"한 경우(예: 강풍이지만 지면이 시원한 저녁)를 표현할 수 없다.

**날씨 상태 색과 산책 단계 색을 분리한다**: 산책 단계는 채운 배지(고채도)로만, 날씨 종류는 연한 칩(저채도)으로만 표현한다. 같은 hue가 겹치더라도 채도·형태로 구분해 판정이 날씨 종류 표시로 오독되지 않게 한다.

### 5.4 다크 모드 — **지원한다** `[현재]`

> 직전 개정의 결정을 뒤집는다. **재검토 조건이 충족됐기 때문이다.**

직전 문서는 다크 모드를 미지원으로 결정하면서 재검토 조건을 명시했다 — *"토큰이 전 컴포넌트에 적용되고 대비비가 전부 통과한 뒤"*. 두 조건이 모두 충족됐다:

| 조건 | 현재 |
| --- | --- |
| 토큰의 전 컴포넌트 적용 | 완료 — 라이브 컴포넌트에 색 리터럴 0건 |
| "지원하려다 만" 상태(body만 어두워짐) | 해소 — 카드·배지·버튼·네비 전부 전환 |
| 대비비 | muted 텍스트를 `#6c757d`→`#5b6472`로 교체해 AA 통과 |

구현은 `base.css:60-85`의 `prefers-color-scheme: dark` 블록에서 **토큰 값만 재정의**한다. 컴포넌트 CSS는 라이트/다크를 모르며, 이것이 두 벌 관리를 피하는 유일한 방법이다.

> 다크 모드는 색을 두 벌 만드는 일이 아니라, 토큰 값을 한 벌 더 정의하는 일이다.

`[예정]`: 5.3의 산책 단계 색도 다크 값을 함께 정의한다. 다크에서 채도를 그대로 쓰면 어두운 배경 위에서 눈부심이 생기므로 명도를 올리고 채도를 낮춘다(현재 의미 토큰이 취한 방식과 동일).

`[결정 필요]`: 시스템 설정과 별개로 사용자가 직접 전환하는 토글을 둘지. 현재는 `prefers-color-scheme`만 따른다.

## 6. 상태 표현 기준

### 6.1 상태 목록과 규격

| 상태 | 보여주는 것 | 레이아웃 이동 방지 | 상태 |
| --- | --- | --- | --- |
| **프로필 없음(초기)** | 온보딩 안내 + 등록 버튼 | 판정 카드와 같은 높이 | `[예정]` |
| 초기 로딩 | 실제 카드와 같은 구조의 스켈레톤 | 실카드와 같은 padding·radius | `[현재]` |
| 갱신 중 | 기존 판정 유지 + 진행 표시 | 기존 내용 유지 | `[예정]` |
| 빈 결과 | 중립 아이콘 + 안내 + 초기화 버튼 | 최소 높이 확보 | `[현재]` |
| 오류 | 위험색 아이콘 + 원인 + 재시도 | 동일 | `[현재]` |
| **부분 실패(예보만 실패)** | 판정은 유지, 타임라인 자리만 접기 | 판정 영역 불변 | `[예정]` |

### 6.2 초기 상태를 빈 결과·오류와 다르게 표현하는 이유

> 프로필 없음은 실패도, 결과 0건도 아니다. 사용자가 아직 시작하지 않았을 뿐이다.

셋을 같은 화면으로 처리하면 첫 방문자가 자기 잘못이라고 느낀다. 오류색(빨강)을 쓰지 않고, 아이콘은 중립, 문구는 "무엇을 하면 되는지"로 쓴다.

**프로필이 없을 때 범용 판정을 보여주지 않는다**(서비스 문서 4.6) — 맞춤이 아닌 판정을 맞춤인 것처럼 보이면 사용자가 자기 개에게 맞는 답이라고 오해한다.

### 6.3 로딩 표현

> 초기 로딩은 스켈레톤, 갱신 중은 인라인 진행 표시. 전면 스피너와 `alert()`는 쓰지 않는다.

스피너는 높이가 거의 없어 스피너→콘텐츠 전환 순간 아래 요소가 수백 px 밀린다. 현재 스켈레톤은 실제 카드와 같은 `padding`·`radius`를 쓴다(`WeatherCardSkeleton.vue:21-27`).

### 6.4 부분 실패

판정(F-23)은 현재 관측만으로 성립하고, 타임라인(F-26)은 예보에 의존한다. 예보가 실패했다고 화면 전체를 오류로 만들면 사용자는 볼 수 있었던 답을 잃는다.

> 화면의 일부가 실패하면 그 일부만 접는다. 실패한 영역이 성공한 영역을 가리지 않는다.

### 6.5 판정 상태

> 색은 판정을 전달하는 세 가지 수단(색·아이콘·텍스트) 중 하나일 뿐이다. 항상 함께 쓴다.

`good` 상태에도 판정 카드는 표시한다 — 카드가 사라지면 "판정이 돌았는지" 알 수 없다. 다만 `good`은 배경 채도를 가장 낮게 두어 강조 총량을 지킨다.

### 6.6 StatusBar의 위치 `[현재]`

> StatusBar는 "직접 조작에 대한 일시적 피드백" 전용이다. 로딩·오류·빈 결과·판정은 절대 StatusBar로 표현하지 않는다.

성공색(초록) 고정을 제거해 "초록색 오류"가 되지 않게 했다.

## 7. 반응형 기준

### 7.1 원칙

> **모바일 우선.** 주 사용 맥락이 **현관 앞, 한 손에 목줄을 쥔 상태**다.

이전 컨셉(외출 직전 확인)보다 제약이 강하다. 한 손 조작이 기본이고, 화면을 오래 볼 수 없다.

| 구간 | 폭 | 우선순위 |
| --- | --- | --- |
| mobile | ~767px | 1순위 |
| desktop | 1120px~ | 2순위 |
| tablet | 768~1119px | 3순위 |

현재 적용된 분기점: 검색 영역 640px(`WeatherHomeView.vue`), 페이지 패딩 768px(`main.css:9-13`).

### 7.2 구간별 변화

카드 목록 1열→2열, 네비게이션 줄바꿈→한 줄, 검색 세로→가로 2단, 좌우 패딩 16→24→32px.

**판정 카드는 구간과 무관하게 1열을 유지한다** — 화면당 최강 강조 1개 규칙(2.6) 때문에 옆에 무언가를 나란히 두지 않는다.

### 7.3 폭 규정 `[현재]`

> `width` 고정을 금지하고 `max-width` + `width:100%`만 사용한다.

최소 지원 폭 320px, 최대 콘텐츠 폭 640px, 페이지 최대 폭 1280px(`main.css:4`).

### 7.4 터치 대상

최소 44×44px, 인접 간격 8px 이상. **한 손 조작 전제이므로 주요 조작(개체 전환, 타임라인)은 화면 하단 절반에 배치한다** — 상단은 엄지가 닿지 않는다.

`[결정 필요]`: 현재 버튼 실측 높이가 44px에 미달하는 곳이 있다. 토큰(`--space-*`) 조합으로 일괄 상향할지, 버튼 전용 최소 높이 토큰을 신설할지.

## 8. 접근성 기준과 광고 배치

### 8.1 접근성을 다루는 이유

> 판정을 읽지 못하는 사용자가 있다면, 그 사용자에게 이 서비스는 작동하지 않는 것이다.

판정 대상이 동물이라 오독의 비용이 크다(서비스 문서 11절).

### 8.2 최소 준수 항목(WCAG 2.1 AA)

| 항목 | 기준 | 상태 |
| --- | --- | --- |
| 본문 대비 | 4.5:1↑ | `[현재]` muted 교체 완료 |
| 문서 언어 | `lang` 지정 | `[현재]` `index.html:2` |
| 배지·버튼 텍스트 | 4.5:1↑ | `[현재]` 토큰 적용 |
| **색 단독 의존 금지** | 색 외 수단 1개↑ | `[현재]` 위험 카드 좌측 바+라벨 / `[예정]` 산책 단계 |
| 오류 알림 | 스크린리더 전달 | `[현재]` `ErrorState.vue` `role="alert"` |
| 장식 요소 숨김 | `aria-hidden` | `[현재]` 스켈레톤 |
| 모션 축소 존중 | `prefers-reduced-motion` | `[현재]` 스켈레톤 애니메이션 |
| 폼 레이블 | 프로그램적 연결 | `[예정]` 검색 `h3`→`<label for>`, 프로필 폼 전체 |
| 포커스 표시 | 2px↑ 가시적 | `[예정]` `:focus-visible` 규칙 신설 |
| 키보드 접근 | Tab+Enter로 전 조작 | `[예정]` 클릭 가능한 `div`(카드) 정정 |
| 헤딩 순서 | 건너뛰기 금지 | `[예정]` h1 부재·h3 시작 정정 |

### 8.3 산책 판정의 접근성 고유 요구 `[예정]`

| 항목 | 규격 |
| --- | --- |
| 단계 전달 | 색 + 아이콘 + **텍스트 라벨** 3중. 색약에서 4단계가 회색으로 수렴하는 것을 막는다 |
| 타임라인 | 막대 색만으로 읽히지 않게 시간·상태를 텍스트로 병기 |
| 가능 시간 | 숫자만 두지 않는다("15" X / "15분 이내" O) |
| 추정 라벨 | 시각적 축약 금지. 스크린리더에도 "추정"이 읽혀야 한다 |

### 8.4 광고 배치 규격

정책(둘지 말지, 어디에)은 [service_architecture.md](./service_architecture.md) 10절이 정한다. 이 절은 시각 규격만 정의한다.

> 광고는 판정과 같은 시각 언어를 쓰지 않는다.

이유: 채운 배경은 이 서비스에서 "지금 행동을 바꿔라"를 독점한다. 광고가 같은 형태를 쓰면 (a) 광고를 판정으로 오인하거나 (b) 판정을 광고로 오인해 무시한다 — (b)가 훨씬 위험하다.

| 항목 | 규격 |
| --- | --- |
| 표기 | 좌상단 "광고" 라벨 |
| 배경/경계 | `surface-sunken` + `border`, 그림자 없음 |
| 최대 높이 | mobile 120px / desktop 160px |
| 색·형태 | **산책 단계색·채운 배지 형태 전부 금지** |
| 배치 금지 구역 | 산책 판정 화면 전체, 타임라인 화면 전체, 카드 목록 중간, 빈 결과/오류/초기 상태 블록 |
| 로딩 실패 | 오류로 취급하지 않고 영역 자체를 제거 |

| 지면온도는 P2이되 시각적으로 P1 허용, 단 "추정" 필수 | 서비스 고유 가치이지만 관측값이 아니다 |

| **다크 모드 지원으로 결정 변경** | 직전 개정이 명시한 재검토 조건(토큰 전면 적용·대비 통과)이 충족됐다 |
| `unsafe`를 "0분"이 아니라 "지금은 어려워요 + 다음 시각"으로 | 숫자 0은 다음 행동을 제시하지 못한다 |
| 부분 실패는 해당 영역만 접는다 | 예보 실패가 판정을 가리면 볼 수 있었던 답을 잃는다 |
| 주요 조작을 화면 하단 절반에 배치 | 한 손에 목줄을 쥔 상태가 기본 사용 맥락이다 |
